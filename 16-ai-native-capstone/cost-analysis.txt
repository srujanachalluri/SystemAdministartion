--------------------------------------------------------------------------------
0. THE QUESTION
--------------------------------------------------------------------------------
CRI is a relief organisation. Every dollar spent on a GPU is a dollar not spent
in the field. So this document is not "how do we make AI cheap." It is:

    WHAT DOES THE ARCHITECTURE COST, WHERE DOES THE MONEY GO, AND WHICH PART OF
    THE BILL IS BUYING SOMETHING OTHER THAN COMPUTE?

The headline finding is uncomfortable and it is stated first, on purpose:
self-hosting the case-note lane costs CRI roughly US$5,860/month MORE than
sending the same tokens to a mid-tier API. We are recommending the more expensive
option. Section 5 explains why, and decision-memo.docx defends it to the board.

--------------------------------------------------------------------------------
1. VRAM SIZING — THE NAPKIN MATH
--------------------------------------------------------------------------------
Model shape (W1, self-hosted case-note lane):
    ~70B-parameter open-weight instruct model, quantised to FP8/INT8
    80 layers, 8 KV heads (grouped-query attention), head_dim 128
    8,192-token context, 24 concurrent requests at peak

    weights                 70 B params x 1 byte/param      =  70.0 GB
    KV cache, per request   2 x 8 kv_heads x 128 head_dim
                            x 2 bytes x 80 layers x 8,192   =   2.68 GB
    KV cache, x24 concurrent                                =  64.4 GB
    runtime overhead (activations, fragmentation) ~12%      =  16.1 GB
                                                              ---------
    TOTAL VRAM REQUIRED                                     = 150.6 GB
    GPUs @ 80 GB                                            = 2

    THE POINT OF THIS SECTION: the KV cache is 48% of live VRAM. It is nearly as
    large as the weights, and unlike the weights IT SCALES WITH LOAD. A sizing
    exercise that counts only "70B params x 1 byte = 70 GB, so one 80 GB card"
    is wrong by a factor of two and will OOM in production the first busy
    afternoon. Grouped-query attention is what keeps this merely large instead of
    catastrophic; with 64 full attention heads instead of 8 KV heads, the same
    cache would be ~515 GB.

    HEADROOM: 2x80 GB holds ~27 concurrent 8k-context requests. CRI peaks at 24.
    That is deliberately thin headroom, and the growth trigger is stated in §6.

STORAGE
    case-note corpus (source documents)                       340 GB
    vector index (2.4M chunks x 1024 dims, float32, HNSW)      15 GB
    immutable backup copy (3-2-1-1-0)                         442 GB
    Note: the index is REBUILDABLE. CRI backs up source documents and the
    embedding configuration, not the index. Cheaper, and it survives an embedding
    model change — which is a when, not an if.

  S1 — FIELD OFFICES DOUBLE

3. THE CROSSOVER — WHERE THE DECISION FLIPS
--------------------------------------------------------------------------------
Crossover = the monthly token volume at which the FIXED self-host bill equals the
VARIABLE API bill. Below it, pay-per-token is cheaper. Above it, own the node.
Workload shape: RAG-like, 91% input / 9% output tokens.

    API tier            blended $/1M tok      crossover (tokens/month)
    ----------------    ----------------      ------------------------
    budget-tier              $ 0.73                  8,828 M
    small-fast-tier          $ 1.36                  4,706 M
    mid-tier                 $ 4.08                  1,569 M
    large-tier               $ 7.25                    883 M

    CRI's W1 volume TODAY:                              132 M tokens/month
    Crossover against the mid-tier API:               1,569 M tokens/month

    CRI IS AT 8% OF THE CROSSOVER VOLUME.
    On cost alone, the API wins today by US$5,860/month (US$70,320/year).

    To reach the crossover on the mid-tier API, CRI's case-note workload would
    have to grow ~11.9x — roughly, every one of the 600 staff running the
    case-note assistant heavily, every working day. That is not a plausible 2030
    number for this organisation, and pretending otherwise would be building the
    business case backwards from the answer we wanted.

4. SENSITIVITY — WHAT UTILISATION DOES TO THE UNIT PRICE
--------------------------------------------------------------------------------
A reserved node bills identically whether it is busy or idle. This table is the
single most important table in the document for anyone about to buy a GPU.

    utilisation    tokens/month    self-host $/1M    vs mid-tier API ($4.08/1M)
    -----------    ------------    --------------    --------------------------
        10%             90 M          $71.11         API cheaper (17.4x)
        15%            135 M          $47.41         API cheaper (11.6x)   <- CRI today
        25%            225 M          $28.44         API cheaper (7.0x)
        40%            360 M          $17.78         API cheaper (4.4x)
        60%            540 M          $11.85         API cheaper (2.9x)
        80%            720 M          $ 8.89         API cheaper (2.2x)
       100%            900 M          $ 7.11         API cheaper (1.7x)

    READ THIS HONESTLY: at this node price and these API prices, the self-hosted
    lane NEVER becomes the cheaper option for CRI — not even at 100% utilisation.
    The unit price falls 10x from 10% to 100% utilisation, which is why
    consolidating every self-hostable workload onto the one node matters, but it
    does not cross the line.

    We are not going to hide that behind an optimistic utilisation assumption. It
    would have been easy to set the node price lower, the API price higher, or
    the utilisation at 90%, and produce a table that "proved" the recommendation.
    A cost model that only ever agrees with the architect is not a cost model.

    WHAT WOULD CHANGE THIS CONCLUSION (stated in advance, so it is falsifiable):
      - A node under ~US$1,800/month all-in at these volumes (e.g. donated or
        grant-funded hardware, or a nonprofit compute credit programme). CRI
        should actively pursue this; it is the single largest lever.
      - W1 volume above ~1,570M tokens/month.
      - A mid-tier API price rise above ~$48/1M blended (implausible; prices have
        moved down, not up).
      - Consolidating W2 and W3 onto the node — but W2/W3 are bursty and the node
        is sized for W1's peak, so this trades cost against latency.

5. THE RECOMMENDATION
--------------------------------------------------------------------------------
CRI SELF-HOSTS W1 (case-note RAG) AND PAYS THE US$5,860/MONTH PREMIUM.
CRI USES THE API LANE FOR W2 AND W3.

The premium is not a compute decision. It buys three things compute cannot:

  (1) DATA RESIDENCY for special-category personal data about vulnerable people.
      The case notes never leave a boundary CRI controls. Contractual zero-
      retention terms with a vendor are a promise; a network that has no route
      to that vendor is a control. After E3 (the chatbot paste), CRI's board is
      not in a position to accept a promise.

  (2) DELETABILITY. A beneficiary who withdraws consent can be removed from an
      index CRI operates, today, verifiably. CRI cannot verify deletion inside a
      third party's logging and abuse-monitoring pipeline, whatever the contract
      says.

  (3) A FIXED, PREDICTABLE BILL for the highest-risk workload. Scenario S1 shows
      it: the organisation can double and this line item does not move. For a
      donor-funded organisation, budget predictability has real value that does
      not appear in a $/token comparison.

  The board should see the US$70,320/year figure plainly. It is roughly 0.6 FTE
  of field staff. That is the trade, stated in the units the board actually
  thinks in, and it is theirs to accept or reject — not the architect's to
  disguise. See decision-memo.docx.

  WHAT WE ARE *NOT* DOING: we are not self-hosting W2 and W3 as well "since we
  already own the node." They are bursty, they hold no RESTRICTED data, and
  putting them on the node would consume the headroom that keeps W1's latency
  acceptable. The duty applies to the case notes, not to everything.

6. GROWTH TRIGGERS AND GUARDRAILS
--------------------------------------------------------------------------------
  TRIGGER 1  Peak concurrency > 24 sustained for 2 weeks, OR p95 time-to-first-
             token > 2s.  -> add a third GPU. Owner: Daniel Okoro.
             (2x80 GB holds ~27 concurrent 8k requests. The margin is 3.)
  TRIGGER 2  Context length raised above 8k. -> RE-RUN THE VRAM MATH FIRST. KV
             cache is linear in context; 16k context doubles the cache to
             ~129 GB and immediately needs a third GPU. Nobody raises the
             context window without re-running estate_cost.py. Owner: Daniel Okoro.
  TRIGGER 3  API lane spend hits the US$200/day cap on 3 days in any month.
             -> Finance review, not a silent cap increase. Owner: Ruth Mensah.
  TRIGGER 4  Node utilisation stays below 10% for two quarters. -> re-open the
             self-host decision. The duty still holds, but at that point CRI
             should be shopping for a smaller node or a nonprofit-priced
             sovereign/residency-guaranteed endpoint. Owner: Ruth Mensah.

  CONSUMPTION GUARDRAILS IN FORCE:
    - US$200/day hard cap on the API lane. Hard stop, not an alert.
    - Per-user and per-agent rate limits; loop detector halts runaway agents
      after N identical tool calls (LLM10, Unbounded Consumption).
    - Every price in this analysis re-verified quarterly by Ruth Mensah. These
      are mid-2026 snapshots and they move weekly.

--------------------------------------------------------------------------------
7. WHAT IS DELIBERATELY NOT IN THIS MODEL
--------------------------------------------------------------------------------
  Stating the gaps is part of the estimate.
  - Staff TIME. Running a GPU node is not free in a nine-person team; the
    US$6,400 includes an allowance for Daniel Okoro's time but not the cost of
    him being unavailable for something else. That is a capacity question and it
    belongs in the decision memo.
  - Egress and inter-region transfer for a four-continent footprint.
  - Fine-tuning or continued pre-training. CRI does none — see ai-strategy §3.
  - The cost of an incident. A single RESTRICTED-data breach involving vulnerable
    beneficiaries would cost CRI more than this entire estate, in a currency the
    organisation cannot replenish: trust. That absence from the spreadsheet is
    precisely why the cheapest option is not automatically the right one.
